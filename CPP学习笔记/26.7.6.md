# Q1：为什么这样就能实现单例模式？禁用赋值和复制的语法我看不懂

```c++
    static Application& GetInstance() {
        static Application instance;
        return instance;
    }
    // Delete copy constructor and assignment operator
    Application(const Application&) = delete;
    Application& operator=(const Application&) = delete;
```

这是 C++ 中经典的 **Meyers 单例模式**，我来逐行解释：

## 1. 单例的核心：`GetInstance()`

```cpp
static Application& GetInstance() {
    static Application instance;
    return instance;
}
```

关键在于 `static Application instance;` 这一行：

- **`static` 局部变量**的生命周期是**整个程序运行期间**，且**只会被初始化一次**。
- C++11 标准保证：局部 `static` 变量的初始化是**线程安全**的（编译器会自动加锁）。
- 返回的是**引用** (`&`)，所以每次调用 `GetInstance()` 都拿到的是**同一个对象**。

这就是单例的本质：**全局只有一个实例，通过统一入口访问。**

## 2. 禁用拷贝和赋值

```cpp
Application(const Application&) = delete;
Application& operator=(const Application&) = delete;
```

这是 C++11 的语法，含义是：

| 语法                                                   | 意思                                                        |
| ------------------------------------------------------ | ----------------------------------------------------------- |
| `Application(const Application&) = delete;`            | **删除拷贝构造函数** — 禁止用已有对象去"复制"出新对象       |
| `Application& operator=(const Application&) = delete;` | **删除拷贝赋值运算符** — 禁止用已有对象去"赋值"给另一个对象 |

### 为什么需要删除？

如果不删除，别人可以这样写：

```cpp
Application a = Application::GetInstance();  // 拷贝了一份！破坏了单例
Application b;
b = Application::GetInstance();              // 又赋值了一份！破坏了单例
```

加了 `= delete` 后，上面这些代码**编译时就会直接报错**，从根本上杜绝了"意外创建副本"的可能。

### 用大白话说

- `= delete` 就是告诉编译器：**"这个函数我不准你用，谁用谁编译报错"**。
- 相比旧写法（声明为 `private` 但不实现），`= delete` 更清晰、报错更早（编译期 vs 链接期）。

## 3. 完整逻辑串联

```
构造函数是 private（在 private 区域）
    → 外面不能 new Application()

GetInstance() 返回唯一的 static 实例
    → 全局只能通过这个入口拿到对象

拷贝构造 = delete
    → 不能复制出新对象

赋值运算 = delete  
    → 不能赋值出新对象

结果：整个程序有且只有一个 Application 实例 ✅
```
