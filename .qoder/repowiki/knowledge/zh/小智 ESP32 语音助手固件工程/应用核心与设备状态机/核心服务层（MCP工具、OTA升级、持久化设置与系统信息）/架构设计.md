本模块由四个独立且低耦合的 C++ 类组成，均位于 `main/` 顶层，通过各自的头文件暴露接口：
- `mcp_server.cc` 实现 `McpServer`，遵循 Model Context Protocol (MCP) 2024-11-05 JSON-RPC 规范，维护一个 `std::vector<McpTool*>` 工具表；`AddCommonTools()` 把常用工具插到列表头部以利用 prompt cache，`AddUserOnlyTools()` 注册仅用户可见的工具（reboot、upgrade_firmware、screen/camera 控制），所有工具回调通过 `Application::Schedule` 投递到主线程执行，解析结果经 `ReplyResult/ReplyError` 统一封装回传。
- `ota.cc` 实现 `Ota`，依赖 `Board::GetInstance().GetNetwork()->CreateHttp(0)` 发起 HTTP 请求，先 `CheckVersion()` 拉取包含 activation/mqtt/websocket/server_time/firmware 字段的 JSON 并写回对应 Settings namespace，再在 `Upgrade()` 中以 4KB 页为单位流式写入 `esp_ota_get_next_update_partition()`，最后 `esp_ota_set_boot_partition` 切换启动项；激活流程使用 ESP32 HMAC Key0 对 challenge 计算签名。
- `settings.cc` 实现 RAII 风格的 `Settings` 包装器，构造时按命名空间打开 NVS，析构时对 dirty 标记的句柄执行 `nvs_commit`，提供 GetString/SetString/GetInt/SetInt/GetBool/SetBool/EraseKey/EraseAll 等类型安全 API。
- `system_info.cc` 提供静态方法 `SystemInfo::GetMacAddress()/GetUserAgent()/GetFlashSize()/PrintTaskCpuUsage()` 等只读探针，根据 `CONFIG_XIAOZHI_USE_ETHERNET`、`CONFIG_IDF_TARGET_ESP32P4` 等编译开关选择 MAC 来源与 WiFi 驱动。
依赖方向单向向下：MCP 工具 → Board/SystemInfo/Settings/Ota，OTA 与 SystemInfo 不反向依赖 MCP，Settings 与 SystemInfo 无相互依赖。
