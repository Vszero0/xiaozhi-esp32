## 一、`#include` 的两种形式

### 你的理解：
- `<>` 里的是标准库，`""` 里的是自定义库 ✅ **基本正确**

### 但在嵌入式开发中需要补充：

```cpp
#include <esp_log.h>        // ESP-IDF 框架提供的日志库
#include <nvs_flash.h>      // ESP-IDF 提供的非易失性存储库
#include <freertos/FreeRTOS.h>  // FreeRTOS 实时操作系统库

#include "application.h"    // 项目自定义的头文件
```

| 形式      | 搜索路径                    | 来源                           |
| --------- | --------------------------- | ------------------------------ |
| `<xxx.h>` | 系统路径 + ESP-IDF 组件路径 | ESP-IDF 框架、FreeRTOS、标准库 |
| `"xxx.h"` | 当前文件所在目录开始搜索    | 项目自定义代码                 |

**注意**：`<freertos/FreeRTOS.h>` 不是 C++ 标准库，而是 **FreeRTOS 实时操作系统**的头文件，由 ESP-IDF 集成提供。

## 二、`#define TAG "main"`

### 你的理解：
- TAG 是说明代码处于 main 状态 ✅ **正确**

### 详细解释：

`TAG` 是 ESP-IDF 日志系统的**标签**，用于在日志输出时标识来源：

```cpp
ESP_LOGI(TAG, "Hello World");  // 输出: I (main) Hello World
ESP_LOGW(TAG, "Warning!");     // 输出: W (main) Warning!
ESP_LOGE(TAG, "Error!");       // 输出: E (main) Error!
```

| 宏         | 含义            | 输出前缀 |
| ---------- | --------------- | -------- |
| `ESP_LOGI` | Info（信息）    | `I`      |
| `ESP_LOGW` | Warning（警告） | `W`      |
| `ESP_LOGE` | Error（错误）   | `E`      |
| `ESP_LOGD` | Debug（调试）   | `D`      |
| `ESP_LOGV` | Verbose（详细） | `V`      |

## 三、`extern "C"` —— 重点纠正！

### 你的理解：
- `extern "C"` 表示使用外部的 C 文件 ❌ **不准确**

### 正确理解：

`extern "C"` 的作用是**告诉 C++ 编译器：这段代码要用 C 语言的方式编译和链接**。

#### 为什么需要它？

C 和 C++ 的函数名**编译后不一样**：

```
C 语言编译：
  函数名: app_main → 编译后符号名: app_main

C++ 语言编译（name mangling）：
  函数名: app_main → 编译后符号名: _Z8app_mainv
```

ESP-IDF 框架是用 **C 语言**写的，它会在启动时查找名为 `app_main` 的函数。如果我们的代码是 `.cc` 文件（C++），编译器会把 `app_main` 变成 `_Z8app_mainv`，框架就找不到入口函数了！

#### `extern "C"` 的效果：

```cpp
extern "C" void app_main(void) {
    // 这段代码用 C 方式编译
    // 函数名保持为 app_main，不变形
}
```

#### 另一种常见写法：

```cpp
extern "C" {
    void app_main(void);
    void another_c_function(void);
}
```

**总结**：`extern "C"` 不是"使用外部C文件"，而是"让这段代码被当作C代码处理"。

## 四、`app_main()` 函数

### 你的理解：
- 启动前检查配置，没问题之后正式启动 ✅ **正确**

### 详细流程：

```
┌──────────────────────────────────────────────────────────┐
│                  ESP32 芯片启动流程                       │
│                                                          │
│  1. 芯片上电 → 2. 加载引导程序 → 3. 初始化硬件            │
│         │                                                │
│         ▼                                                │
│  4. ESP-IDF 框架初始化                                   │
│         │                                                │
│         ▼                                                │
│  5. 调用 app_main() ← 这是我们的代码入口！               │
│         │                                                │
│         ├── 5.1 初始化 NVS Flash（保存 WiFi 配置等）      │
│         │                                                │
│         ├── 5.2 创建 Application 单例                   │
│         │                                                │
│         ├── 5.3 调用 Initialize() 初始化                  │
│         │                                                │
│         └── 5.4 调用 Run() 进入主事件循环（永不返回）      │
└──────────────────────────────────────────────────────────┘
```

### NVS Flash 初始化详解：

```cpp
esp_err_t ret = nvs_flash_init();
if (ret == ESP_ERR_NVS_NO_FREE_PAGES || ret == ESP_ERR_NVS_NEW_VERSION_FOUND) {
    // NVS 存储损坏或版本不兼容，需要擦除
    ESP_ERROR_CHECK(nvs_flash_erase());
    ret = nvs_flash_init();
}
ESP_ERROR_CHECK(ret);
```

**NVS（Non-Volatile Storage）** 是 ESP32 的非易失性存储，类似电脑的注册表，保存：
- WiFi SSID 和密码
- 用户配置
- 设备激活信息
- 等等

如果 NVS 损坏，就擦除后重新初始化。

## 四、每个模块的学习方法

### 1. 学习单个类的方法

```
1. 先看 .h 文件（头文件）
   ├── 类声明
   ├── 成员变量（理解类的数据结构）
   ├── 成员函数（理解类提供的接口）
   └── 虚函数（理解继承关系）

2. 再看 .cc 文件（实现文件）
   ├── 构造函数（如何初始化）
   ├── 核心方法（业务逻辑）
   └── 调用关系（依赖哪些其他类）

3. 思考问题
   ├── 这个类的职责是什么？
   ├── 它如何与其他类交互？
   ├── 使用了什么设计模式？
   └── 如果让我写，会怎么设计？
```

### 2. 以 Application 为例的学习步骤

```
步骤1：看 application.h
   ├── 发现是单例模式
   ├── 成员变量：event_group_, audio_service_, protocol_
   ├── 成员函数：Initialize(), Run(), SetDeviceState()
   └── 虚函数：无（Application 不是基类）

步骤2：看 application.cc 的构造函数
   ├── 创建 event_group_
   ├── 创建定时器（Lambda 回调）
   └── 设置 AEC 模式

步骤3：看 Initialize()
   ├── 获取 Board 实例
   ├── 初始化 Display
   ├── 初始化 AudioService（设置回调）
   ├── 注册状态变化监听器
   └── 启动定时器

步骤4：看 Run()
   ├── 事件循环（xEventGroupWaitBits）
   ├── 根据事件调用不同处理函数
   └── 永不返回

步骤5：思考
   ├── Application 是整个系统的核心调度器
   ├── 使用事件驱动模式解耦模块
   ├── 通过 Board 抽象屏蔽硬件差异
   └── 通过回调机制实现异步通信
```
